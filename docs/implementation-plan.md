# LogiBatteryDock 今後の実装方針

更新日: 2026-09-03

## 1. 目的と優先順位

G HUBを任意の優先ソースとして利用しつつ、Logicool / Logitechデバイスの取得可能な状態を確認できる軽量なWindows常駐アプリを目指す。G HUBが動いている場合はその`percentage`を使い、使えない場合はHID++へ戻る。主画面はTwinkle Trayのようなトレイクリック式フライアウトとし、Command PaletteとDockはトレイとは独立した追加の入口にする。両者は同じCore実装を使うが、同じ実行中プロセスの状態を前提にしない。

実装順序は **通信と状態管理の信頼性 → トレイUI → 設定と常駐運用 → Command Palette / Dock → 配布** とする。現時点では計画であり、以下の完了条件を満たすまで実装済み・検証済みとは扱わない。

## 2. 変更しない前提

- デバイスが直接返す％と、G HUBローカルエージェントの`percentage`は「取得値」としてそのまま表示する。これは機器内部／G HUBの算出精度を保証する「実残量」ではないため、取得元を状態に残す。
- `0x1001`のデコーダーは電圧・状態フラグを保持し、`Percent=null`のままにする。G HUBが利用できないフォールバック段階だけ、公開互換実装と同じ汎用カーブで表示用の推定％を付与する。推定値は`NativeVoltageEstimate`として扱い、詳細に「標準カーブ推定」と明記する。
- G HUBとNative HID++の残量変換は別系統として扱う。G HUB稼働中はローカルエージェントの`percentage`をそのまま使い、Native HID++側へ観測点を名前照合・永続化・補正適用しない。単一の電圧と％のペアは、丸め・負荷・温度・経年差を含むため、フォールバックの校正根拠にしない。
- 電圧フォールバックは公開された汎用カーブだけで動作し、カタログ容量や機種名の直書きを変換式へ入れない。将来、機種別データを追加する場合は、個体識別、複数点、単調性、経時・電池交換時の無効化を満たす別設計として検証する。

この分離方針は、公開互換実装がNative HID++の汎用カーブとG HUBの機種別ルックアップテーブルを別系統として扱っていること、および単一観測点では一時的な電圧変動を除外できないことを根拠に選んだ。名前照合と永続ペア補正を残す案は、別個体・電池交換・温度差へ誤補正を持ち越すため採用しない。将来、G HUBの仕様資料または個体単位で複数回再現する実測テーブルが得られ、単調性と無効化条件をテストできる場合だけ再検討する。[LGSNotifyBattery](https://github.com/nixxquality/LGSNotifyBattery)
- 無応答だけでスリープ、圏外、電源OFFのいずれかに断定しない。受信機の不在、通信失敗、機能非対応も区別する。
- 古い取得値を現在値として表示しない。正常取得時刻と確認試行時刻を分ける。
- G HUBの設定変更、終了、アンインストールを必要条件にしない。DPI、マクロ、RGB、ファームウェア等の書き換えは当面対象外。

過去の作業記録ではG703から`0x1001`、`4161 mV`、`Percent=null`を取得し、その際G HUBも稼働していた。2026-09-02の再測定では同じG703から`0x1001`、`3969 mV`、`Percent=null`、`PowerState=Discharging`を取得し、G HUBは`71%`を返した。最新の実機確認ではネイティブが`3921 mV`、G HUBが`70%`となり、ProbeとトレイIPCも`70%`を表示した。この一致は汎用カーブの一地点で偶然一致した結果であり、G HUB校正の証拠にはしない。後の無応答は別実装でも観測されたが、スリープが原因と確定したわけではない。

## 4. 目標構成

既存のC# / .NET、WinUI 3、H.NotifyIcon、HidSharpを継続使用する。必要性が検証されるまで通信ライブラリの置換や常駐サービスの追加は行わない。

- **Core**: HID入出力、HID++要求応答、機能別デコーダーを分離する。UIなしでテスト可能にする。
- **アプリ内監視処理**: 通信ハンドル、更新周期、機器ごとの状態を所有する。手動更新と定期更新を直列化する。
- **共有Core**: G HUBエージェント（任意）とHID++（フォールバック）の取得元を選択し、Native HID++の電圧専用機器には汎用カーブを適用する。デバイス識別子、受信機の識別、対応機能、取得値、取得元、推定フラグ、正常取得時刻、確認試行時刻、接続状態、失敗理由を扱う。実行中の状態は各フロントエンドが個別に所有する。
- **トレイUI**: 状態を表示するだけにし、推定の計算はCoreへ集約する。推定％は主表示にも出すが、詳細で取得元と推定根拠を明示する。
- **Command Palette拡張**: 別プロセスでCore/G HUB/HID++を直接開く。トレイアプリや名前付きパイプが停止・未作成でも状態取得を開始できる。トレイIPCを使う場合も任意の補助連携に限定する。

状態は機器単位で管理する。同じPIDの受信機を別個体として区別し、シリアル等がない場合はセッション内識別と永続識別の限界を明記する。受信機スロットだけを永続的な機器IDにしない。

## 5. 段階別の作業と完了条件

### P0 — 通信と状態管理の信頼性

主な対象: `LogitechDeviceReader.cs`、`HidppProtocol.cs`、`DeviceTelemetry.cs`、`TrayViewModel.cs`。

1. HID入出力を差し替え可能にし、`tests/LogiBatteryDock.Core.Tests/`に通信モックと状態遷移テストを追加する。テスト用フレームは由来と期待値を記録する。
2. 列挙失敗、オープン失敗、無応答、機能非対応、電池取得失敗、不正応答をスナップショットの失敗理由として区別する。列挙・オープン・更新の例外をUIまで未処理で流さない。
3. 通常応答だけでなくエラー応答も、機器・機能・関数・software IDを照合する。短いエラーフレーム、他アプリ宛ての応答、遅延応答をテストする。
4. `ReadName`の`byte`オフセットは長い名前で周回し得るため、整数カウンターと上限で処理する。フレーム長、不完全な名前、キャンセル、全処理の時間制限も確認する。
5. `0x1000`と`0x1004`の有効範囲、0の意味、能力情報、充電状態の意味を一次仕様と実機で個別確認する。G HUBが稼働している場合はローカルWebSocketの`/devices/list`と`/battery/{id}/state`を優先し、返された`percentage`をそのまま状態へ記録する。現在の共通デコーダーを仕様確認の代わりにしない。
6. `MI_02` / `COL02`のパス条件は現在の限定的な探索条件として扱い、一般的な機種対応とはしない。受信機数をPIDの種類数で数える処理も改める。
7. 全台無応答だけでなく、一台だけ消えた場合も状態を保持する。受信機を抜いた場合と機器だけ無応答の場合を分け、古い％は主表示から外して詳細に取得時刻付きで残す。

**進捗**: 電池デコーダーを独立させ、`0x1001`から直接％を生成しないこと、不正電圧・不正％・短いフレームを拒否すること、HID++セッションのping・エラー・名前取得オフセット・キャンセルを固定テストした。G HUB稼働時はエージェントの`percentage`をそのまま返し、Native HID++は公開互換実装に合わせた汎用カーブだけで`NativeVoltageEstimate`を作る。G HUBとNative HID++の読み取りを不要に並列化せず、名前照合・観測点保存・永続校正は行わない。読み取りスナップショットは列挙・オープン・無応答・機能非対応・電池取得失敗・不正応答・全体スキャン時間切れを区別し、受信機キー、成功値の取得時刻、確認試行時刻を持つ。表示ポリシーはCoreへ集約し、推定フラグと取得元をトレイ／CmdPal／IPCへ渡す。受信機が残っている間の一部無応答は、機器ID単位で最終取得値として保持する。ユーザー別設定は検証済みJSONを原子的に保存し、壊れた設定は既定値に戻す。設定画面から更新間隔と自動起動を保存でき、自動起動はHKCU Runのユーザー権限で登録・解除する。アプリ終了時はスキャンキャンセルを発火する。

**完了条件**: HID入出力を差し替え可能にし、同一PIDの複数受信機と一部機器の無応答を模擬テストで確認する。実機未確認の機能は未確認と記録する。

### P1 — トレイの操作と外観

主な対象: `TrayResources.xaml`、表示用モデル、必要に応じた専用フライアウトWindow。

- 左クリックで開閉、外側クリック・Escで閉じる動作を検証する。表示位置をトレイ位置、モニター、作業領域に合わせる。
- 主表示を名前、取得できる残量、接続・電源状態に絞る。電圧、機能ID、生フラグは詳細へ移す。
- 長い機器名、複数台、空状態、取得失敗、古い値を表示できるレイアウトにする。項目が多い場合は高さ制限とスクロールを設ける。
- DPI、ライト／ダーク、高コントラスト、キーボード操作、読み上げ用ラベルを確認する。現在の単色アイコンを識別しやすい機器アイコンへ改善する。
- H.NotifyIconの既存ポップアップで操作要件を満たせるか先に確認する。専用WindowやDesktop Acrylicへの変更はその結果で判断する。
- 2026-09-03時点では、縦に大きいカードを廃止し、名前・接続状態・残量を1台1行へまとめた。電圧やHID++の詳細は行のツールチップへ移し、表示領域を幅340・高さ360に制限している。通知領域のホバーには全機器を並べるカスタムツールチップを追加し、アイコンを`Segoe MDL2 Assets`のマウス glyphと背景付き生成アイコンへ変更した。

**完了条件**: 実画面のスクリーンショットと操作結果で確認する。hidden desktopでプロセスが生存しているだけでは外観・開閉操作を合格にしない。

### P2 — 設定と常駐運用

- 単一起動、二重起動時の既存画面表示、終了時のキャンセルとHIDハンドル解放を実装する。
- 自動起動、表示対象と並び順、診断情報の出力を設定可能にする。自動起動の登録は利用者が有効にした場合だけ行う。更新間隔と自動起動の設定画面、HKCU Run登録・解除、Dockの常駐表示端末選択まで実装し、並び順・診断出力は未実装。
- 設定はユーザー別の`%LOCALAPPDATA%/LogiBatteryDock/`に保存し、バージョン、入力検証、破損時の復旧を設ける。生の機器パスやシリアルを診断ログへ無条件に出さない。
- OSの接続通知やHID++イベントを利用する方式を検証し、定期確認を補助として残す。全スロット・全機能の毎回探索は減らし、再接続時にキャッシュを再検証する。
- スリープ復帰、受信機の抜き差し、Explorer再起動、G HUB同時稼働時の応答率とCPU・メモリ・問い合わせ頻度を測定する。

**完了条件**: 上記の状態変化から再起動なしで復帰し、終了後に監視処理が残らない。設定変更が次回更新へ反映され、自動起動の登録・解除を再起動後も確認する。負荷を測定値で記録し、根拠のない「軽量」判定をしない。

### P3 — Command Palette / Dock

公式資料では拡張は別プロセスで動作し、パッケージのmanifestから登録される。追加プロジェクト`src/LogiBatteryDock.CmdPal/`で扱い、トレイアプリの単独利用も維持する。[拡張の構造](https://learn.microsoft.com/en-us/windows/powertoys/command-palette/extensibility-overview)

- CmdPalはCoreの読み取りサービスを自プロセスに構築する。初回表示では非同期取得中を示し、手動更新は選択した機器／状態行の`MoreCommands`から同じプロセスの読み取りを再実行する。更新を常時表示の独立行にはしない。トレイ本体の停止、IPC切断、未インストールをエラー扱いにしない。
- 初期機能は機器一覧、状態確認、更新要求、デバイス別Dock項目に限定する。「トレイを開く」は独立性を壊す必須機能になるためCmdPalの初期機能から外す。必要になった場合は起動連携として別契約で追加する。
- Dockは`GetDockBands()`で公開し、選択した1台を機器ごとの安定したIDで常駐表示する。右クリックの端末項目を選ぶと`DockDeviceId`を保存し、次回起動後も同じ端末を復元する。公式資料には動的な表示更新も示されている。[Dock対応](https://learn.microsoft.com/en-us/windows/powertoys/command-palette/adding-dock-support)
- 取得できる％を優先し、`0x1001`しか返さない機種でもG HUB停止時は汎用カーブによる推定％を表示する。G HUBの`percentage`とNative HID++の推定値は取得元を分けて保持するが、CmdPalの主表示ではどちらも％として表示する。Dock設定は自動で変更せず、右クリックの明示的な端末選択だけで更新する。
- ページとDockのデバイス行は左クリックで機器情報を表示し、クリップボードコピー操作は提供しない。Dockの右クリック項目は常駐表示端末の選択と更新に限定する。モデル名は先頭の型番を優先した上限付きラベル、サブタイトルは残量と接続状態に限定し、推定％に`（推定）`は付けない。
- パッケージの通常アプリ入口は`AppListEntry="none"`にし、Command Paletteの`windows.appExtension`だけを検索入口として公開する。開発中の`bin/`、`obj/`、`AppPackages/`はホストのファイル検索へ混入し得るため、実画面確認前に生成物を整理する。
- 開発開始時にPowerToysとSDKの対応版を確認・固定する。開発版のインストール更新は`tools/install_cmdpal_dev.ps1`で版数を繰り上げて再登録する。PowerToys実画面での動的表示更新は本書では未検証。

**進捗**: `src/LogiBatteryDock.CmdPal`に公式SDKのCOMサーバー、独立したCore読み取り（G HUBエージェント優先、HID++＋汎用電圧フォールバック）、機器情報ページ、選択行の`MoreCommands`から実行する手動更新、選択端末だけを常駐表示するDockバンドを実装した。Dockの右クリック項目から選んだ機器IDは共有設定へ保存し、左クリックの機器情報ページとは分離している。ページとDockは同じCmdPalプロセス内ストアを参照し、トレイIPCのクライアントコードとトレイ起動操作を持たない。SDK版は`Microsoft.CommandPalette.Extensions 0.11.260520004`などに固定し、`dotnet publish -p:GenerateAppxPackageOnBuild=true`でx64テストMSIXを生成できる。登録済み開発版を実画面や登録状態の確認へ反映する場合は`tools/install_cmdpal_dev.ps1`を使い、パッケージ版数の繰り上げ、開発用署名、現在ユーザーへの登録、必要なCmdPal再起動まで再現できる。通常のビルドだけではインストール処理を行わない。`AppListEntry="none"`後の`Get-StartApps`に拡張ホストは出なくなった。G HUBの`percentage`はCoreで取得元を明示して表示へ渡し、G HUB停止時も0x1001の汎用カーブ推定％と根拠を表示する。独立読み取りはテストと実機Probe／トレイIPCで確認したが、実画面の一覧・Dock描画、固定項目、停止／再起動時の値更新は未確認として残す。添付画面の大量表示は複数プロバイダーではなく、リポジトリの生成済み実行ファイルをホスト検索が拾ったものと切り分けた。

**完了条件**: トレイ本体を停止した状態でもCmdPalが独自に読み取り、CmdPalを停止した状態でもトレイが更新できることを模擬テストと実機スモークで確認する。一覧とDockは同じCmdPal内状態から表示する。本体のIPC切断はCmdPalの機能停止にならないこと、機器の不在、固定項目の復元をPowerToys実画面で確認する。登録・COM起動だけでは完了扱いにしない。
